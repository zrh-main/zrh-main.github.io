Spring Cloud

一、核心组件类（入门必问）

  1. SpringCloud 是什么？核心解决什么问题？
    SpringCloud 是基于 SpringBoot 的微服务全家桶，封装了各种微服务组件。
    核心解决：服务注册发现、负载均衡、熔断降级、网关路由、配置中心、链路追踪等微服务架构的核心问题。
  2. 常用的 SpringCloud 组件有哪些？各自作用？
    服务注册发现：Eureka/Nacos/Consul（管理服务地址，让服务能找到彼此）；
    负载均衡：Ribbon/OpenFeign（客户端负载均衡，分发请求到不同服务实例）；
    熔断降级：Hystrix/Sentinel（服务故障时避免雪崩，返回兜底结果）；
    网关：Gateway/SpringCloud Gateway（统一入口，路由、鉴权、限流）；
    配置中心：Nacos/Config（统一管理配置，不用改代码重启服务）；
    链路追踪：Sleuth+Zipkin（追踪请求链路，排查微服务调用问题）。
  3. Eureka 的核心原理？CAP 怎么选？
    Eureka 是服务注册中心，核心是心跳机制 + 自我保护：
    服务启动注册到 Eureka，每隔 30s 发心跳，Eureka90s 没收到心跳就剔除服务；
    自我保护：网络波动时，Eureka 不会剔除大量服务，保证可用性；
    CAP 选AP（可用性 + 分区容错），牺牲强一致性，适合微服务高可用场景。
  4. Nacos 和 Eureka 区别？
    功能：Nacos 不仅能做注册中心，还能做配置中心，Eureka 只有注册发现；
    CAP：Nacos 支持 AP 和 CP 切换（默认 AP），Eureka 只支持 AP；
    易用性：Nacos 部署简单，支持动态配置刷新，Eureka 已停更。
  5. OpenFeign 是什么？和 RestTemplate 区别？
    OpenFeign 是声明式 HTTP 客户端，基于 Ribbon 实现负载均衡；
    RestTemplate：需要手动拼 URL、调方法，代码繁琐；
    OpenFeign：只需要写接口加注解（@FeignClient），像调本地方法一样调远程服务，更简洁。
    二、核心原理类（进阶考察）
  6. 什么是服务熔断、服务降级？区别是什么？
    熔断：服务调用方做的，目标服务故障（比如超时、报错），触发熔断，暂时停止调用，避免拖垮自己（像保险丝烧断）；
    降级：服务提供方 / 调用方都能做，系统压力大时，主动关闭非核心功能，返回兜底数据（比如 “服务繁忙，请稍后”）；
    核心区别：熔断是被动（故障触发），降级是主动（资源不足时触发）。
  7. Ribbon 负载均衡策略有哪些？默认是什么？
    常用策略：轮询（默认）、随机、权重、重试、最小并发；
    默认是轮询，可以自定义策略（比如按权重分配请求）。
  8. SpringCloud Gateway 核心原理？
    Gateway 是基于 WebFlux 的网关，核心是路由 + 过滤器链：
    路由：匹配请求路径，转发到对应服务；
    过滤器：分全局过滤器（所有请求生效）和局部过滤器（指定路由生效），能做鉴权、限流、日志、修改请求 / 响应；
    异步非阻塞，性能比 Zuul 好。
  9. 什么是服务雪崩？怎么避免？
    服务雪崩：一个服务故障，导致调用它的所有服务都故障，连锁反应拖垮整个系统；
    避免手段：
    ① 熔断（Hystrix/Sentinel）：故障服务触发熔断，停止调用；
    ② 降级：核心服务优先，非核心服务降级；
    ③ 限流：网关 / 服务端限流，控制请求数；
    ④ 超时控制：设置调用超时时间，避免长时间等待。
  10. Nacos 配置中心实现动态刷新的原理？
    ① 服务启动时从 Nacos 拉取配置，同时和 Nacos 建立长连接；
    ② 配置修改后，Nacos 主动推送配置变更给服务；
    ③ 服务收到通知后，重新加载配置，配合 @RefreshScope 注解，Bean 属性动态更新，不用重启服务。
    三、实战场景类（场景考察）
  11. 微服务之间如何实现远程调用？
    常用两种方式：
    ① RestTemplate + Ribbon：RestTemplate 做 HTTP 调用，Ribbon 做负载均衡；
    ② OpenFeign：声明式调用，底层还是 Ribbon，代码更简洁，推荐用这个。
  12. 如何实现微服务接口的统一鉴权？
    在 Gateway 网关层做统一鉴权：
    ① 前端请求带 token，网关拦截所有请求；
    ② 校验 token 合法性（比如查 Redis、调认证服务）；
    ③ 合法则转发请求，不合法直接返回 401，不用每个服务都写鉴权逻辑。
  13. 微服务如何实现分布式事务？
    主流方案：
    ① 最终一致性：Seata（AT 模式，无侵入，适合大多数场景）；
    ② 补偿机制：TCC（Try-Confirm-Cancel，手动写补偿逻辑，适合核心业务）；
    ③ 消息队列：本地消息表 + MQ，异步补偿，保证最终一致。
  14. 如何做微服务的限流？
    ① 网关层限流：Gateway 结合 Sentinel/Nacos，按 IP / 接口限流（比如每秒最多 100 个请求）；
    ② 服务端限流：Sentinel 注解（@SentinelResource），对具体接口限流，触发后返回降级结果。
  15. 微服务项目如何部署？
    ① 单体部署：每个微服务打包成 jar，部署到不同服务器，配合 Nginx 做负载；
    ② 容器化部署：打包成 Docker 镜像，用 K8s/Docker Compose 管理，自动扩缩容；
    ③ 注册中心、配置中心等中间件单独部署，保证高可用（比如 Eureka 集群、Nacos 集群）。
    四、问题排查类（高频加分项）
  16. 微服务调用超时，怎么排查？
    ① 查网络：是否能 ping 通目标服务，端口是否开放；
    ② 查注册中心：目标服务是否注册成功，实例状态是否正常；
    ③ 查日志：看调用方和提供方的日志，是否有报错（比如数据库慢查询、接口抛异常）；
    ④ 查配置：是否设置了合理的超时时间（Feign/Hystrix 超时）。
  17. 服务注册到 Nacos/Eureka 失败，原因有哪些？
    ① 配置错误：注册中心地址写错、服务名重复、端口冲突；
    ② 网络问题：服务连不上注册中心；
    ③ 依赖缺失：没引入对应的 starter（比如 nacos-discovery）；
    ④ 版本不兼容：SpringBoot 和 SpringCloud 版本不匹配。
  18. Gateway 路由转发失败，怎么排查？
    ① 查路由配置：路径匹配规则是否正确（比如路径少写 /）；
    ② 查服务地址：转发的服务名是否在注册中心存在；
    ③ 查过滤器：是否有过滤器拦截了请求（比如鉴权失败）；
    ④ 查日志：开启 Gateway 日志，看转发的具体地址和错误信息。

Spring Cloud Alibaba

  1. Spring Cloud Alibaba 是什么？核心优势是什么？
    SC-A 是阿里开源的微服务框架，基于 SpringCloud 标准，整合了阿里自研的中间件。
    核心优势：① 组件本土化（Nacos/Sentinel/Seata 都是阿里的，适配国内场景）；② 功能全（注册、配置、熔断、事务一站式解决）；③ 易用性高，文档全，社区活跃。
  2. Spring Cloud Alibaba 核心组件有哪些？各自作用？
    Nacos：一站式注册中心 + 配置中心，替代 Eureka+Config；
    Sentinel：熔断降级 + 限流，替代 Hystrix；
    Seata：分布式事务解决方案，解决微服务跨库事务问题；
    RocketMQ：消息队列，做异步通信、削峰填谷；
    Dubbo：高性能 RPC 框架，替代 OpenFeign（适合高性能服务调用）；
    Gateway：和 SpringCloud Gateway 一致，做微服务网关。
  3. Nacos 有哪两种部署模式？区别是什么？
    单机模式：单节点部署，适合开发测试，不保证高可用；
    集群模式：多节点部署，配合 MySQL 做数据持久化，生产环境必用，保证高可用；
    补充：Nacos 还有伪集群模式（单服务器多端口），仅用于测试，不推荐生产。
  4. Sentinel 核心概念有哪些？
    资源：被保护的对象（接口、方法）；
    规则：限流 / 熔断 / 降级规则（比如 QPS 限流、异常比例熔断）；
    插槽链（Slot Chain）：Sentinel 的核心执行链路，负责规则校验、统计、限流等；
    兜底策略：触发规则后返回的结果（默认、自定义、降级调用）。
  5. Seata 有哪些事务模式？默认是什么？
    AT 模式（默认）：无侵入，基于本地事务 + 补偿，适合大多数场景；
    TCC 模式：手动写 Try/Confirm/Cancel，侵入性强，适合核心高一致性业务；
    SAGA 模式：长事务解决方案，基于状态机补偿；
    XA 模式：强一致性，性能差，极少用。
    二、核心原理类（进阶考察）
  6. Nacos 服务注册发现的原理？
    ① 服务启动时，通过 Nacos Client 向 Nacos Server 注册（提交服务名、IP、端口）；
    ② Nacos Server 将服务信息存在注册表，同时和客户端建立长连接；
    ③ 服务消费者拉取注册表，本地缓存；
    ④ 服务上下线时，Nacos Server 主动推送变更给消费者，保证数据实时性。
  7. Sentinel 限流的核心原理？
    Sentinel 基于令牌桶 / 漏桶算法实现限流，核心是插槽链：
    ① 所有请求先经过 NodeSelectorSlot（构建调用节点）；
    ② 再经过 StatisticSlot（统计 QPS、异常数）；
    ③ 最后经过 FlowSlot（校验限流规则），触发规则则拦截请求，执行兜底策略。
  8. Seata AT 模式的执行流程（简单说）？
    ① 事务发起方开启全局事务，生成 XID（全局事务 ID）；
    ② 调用各微服务，XID 透传，各服务执行本地 SQL，Seata 拦截并记录 undo_log（回滚日志）；
    ③ 所有服务本地事务提交成功，发起方提交全局事务，Seata 删除 undo_log；
    ④ 若有服务失败，发起方回滚全局事务，Seata 根据 undo_log 回滚各服务数据。
  9. Nacos 配置中心如何保证配置不丢失？
    ① 单机模式：配置存在本地文件；
    ② 集群模式：配置持久化到 MySQL，同时 Nacos 节点间同步配置；
    ③ 客户端本地缓存：服务拉取配置后，本地会缓存一份，即使 Nacos 宕机，服务也能读取本地缓存启动。
  10. Sentinel 和 Hystrix 的区别？
    功能：Sentinel 支持限流、熔断、降级、热点规则，Hystrix 主要是熔断降级；
    实时性：Sentinel 规则可动态配置，实时生效；Hystrix 改规则需重启；
    易用性：Sentinel 有可视化控制台，配置简单；Hystrix 配置复杂；
    性能：Sentinel 基于 Netty，异步非阻塞，性能比 Hystrix 好。
    三、实战场景类（场景考察）
  11. 如何用 Sentinel 实现接口限流？
    ① 引入 sentinel-spring-cloud-starter 依赖；
    ② 启动类加 @EnableDiscoveryClient（注册到 Nacos）；
    ③ 接口上加 @SentinelResource（指定资源名、兜底方法）；
    ④ 登录 Sentinel 控制台，给该资源配置限流规则（比如 QPS=10）；
    ⑤ 触发限流时，自动执行兜底方法返回结果。
  12. 微服务如何接入 Nacos 配置中心？
    ① 引入 nacos-config-spring-boot-starter 依赖；
    ② 配置文件写 Nacos 地址、配置 DataID、分组；
    ③ 启动类加 @EnableNacosConfig；
    ④ 需要动态刷新的 Bean 加 @RefreshScope；
    ⑤ Nacos 控制台修改配置，服务自动刷新。
  13. 如何解决 Seata 分布式事务中的 XID 透传问题？
    XID 是全局事务 ID，必须在微服务调用间透传，否则 Seata 无法识别全局事务：
    ① 用 OpenFeign 调用时，自定义拦截器，把 XID 从 ThreadLocal 取出来，放到请求头；
    ② 服务提供方拦截请求，从请求头取出 XID，设置到 ThreadLocal；
    ③ Dubbo 调用时，通过 Dubbo 的上下文传递 XID，原理和 Feign 一致。
  14. 如何实现微服务的灰度发布（基于 Nacos）？
    ① 给服务实例打版本标签（比如 version=v1、v2）；
    ② 配置 Nacos 权重，v1 实例权重 100（全量流量），v2 实例权重 0；
    ③ 逐步提高 v2 权重（比如 20%、50%），观察无问题后全量切到 v2；
    ④ 也可以通过 Nacos 的元数据，配合 Gateway 路由，按用户 / IP 路由到不同版本。
  15. Sentinel 如何做熔断降级？
    ① 配置熔断规则（比如异常比例 > 50%、异常数 > 10，熔断时长 5s）；
    ② 服务调用异常触发规则后，进入熔断状态，期间不调用目标服务；
    ③ 熔断时长结束后，进入半开状态，放少量请求测试，若正常则恢复，否则继续熔断。
    四、对比选型类（高频加分项）
  16. Spring Cloud Alibaba 和原生 Spring Cloud 区别？
    组件：SC-A 用 Nacos/Sentinel/Seata，原生用 Eureka/Hystrix/Config；
    生态：SC-A 组件都是阿里维护，活跃；原生很多组件（Eureka/Hystrix）已停更；
    性能：SC-A 的 Dubbo/Sentinel 性能优于原生的 OpenFeign/Hystrix；
    适配性：SC-A 更适配国内中间件（MySQL、RocketMQ），适合国内项目。
  17. Nacos 作为配置中心，和 Apollo 区别？
    易用性：Nacos 部署简单，轻量；Apollo 部署复杂（需多个组件）；
    功能：Apollo 配置粒度更细（支持环境、集群、命名空间），Nacos 更轻量化；
    生态：Nacos 和 SC-A 深度整合，Apollo 适配所有微服务框架；
    选择：中小项目用 Nacos，大型项目对配置管理要求高用 Apollo。
  18. Seata 和 RocketMQ 事务消息怎么选？
    Seata AT 模式：适合同步调用的分布式事务，实时性高；
    RocketMQ 事务消息：适合异步场景（比如下单后异步扣库存），最终一致性；
    核心：同步业务用 Seata，异步业务用 RocketMQ 事务消息。

用 Nacos 做服务注册发现和配置中心，Sentinel 做流量控制和熔断降级，OpenFeign 做服务间远程调用，Seata 处理分布式事务，这些都用到了

微服务调用超时怎么处理？
答：给 OpenFeign 设置调用超时时间；通过 Sentinel 配置降级规则，超时返回兜底数据，防止服务雪崩

Spring Cloud Bus 实现配置热更新的原理？
答：Nacos 修改配置后发送消息，Bus 基于 RabbitMQ 将配置推送给所有微服务实例，实例自动刷新配置无需重启，项目中管理员修改权限可实时生效。
