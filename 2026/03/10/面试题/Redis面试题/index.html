Redis

  1. Redis 是什么？核心优势是什么？
    Redis 是基于内存的键值对数据库，支持多种数据结构。
    核心优势：① 高性能（纯内存操作，单线程模型）；② 高可用（主从、哨兵、集群）；③ 功能丰富（缓存、分布式锁、消息队列都能做）；④ 支持持久化，数据不丢。

  2. Redis 为什么这么快？
    核心原因：① 纯内存操作，避免磁盘 IO；② 单线程模型，无线程切换、锁竞争开销；③ 用 IO 多路复用（epoll）处理网络请求，高效管理连接；④ 数据结构优化（比如跳表、压缩列表）。

  3. Redis 支持哪些数据类型？各自典型场景？
    String：缓存、计数器、分布式锁（setnx）；
    Hash：存储对象（比如用户信息），节省内存；
    List：消息队列、最新列表（比如朋友圈动态）；
    Set：去重、抽奖、交集并集（比如共同好友）；
    ZSet：排序场景（比如排行榜、延时队列）；
    补充：还有 Bitmap（布隆过滤器）、Geo（地理位置）等扩展类型。

  4. Redis 持久化有哪两种方式？区别是什么？
    RDB：快照持久化，定时把内存数据快照保存到磁盘；优点是恢复快，缺点是可能丢数据；
    AOF：日志持久化，记录所有写命令，重启时重放命令恢复；优点是数据更安全，缺点是文件大、恢复慢；
    生产常用：RDB+AOF 混合，兼顾性能和数据安全。
    二、核心原理类（进阶考察）

  5. Redis 缓存穿透、缓存击穿、缓存雪崩是什么？怎么解决？
    缓存穿透：请求不存在的 key，每次都查数据库；解决：布隆过滤器拦截、空值缓存；
    缓存击穿：热点 key 过期，大量请求打数据库；解决：热点 key 永不过期、互斥锁；
    缓存雪崩：大量 key 同时过期，数据库扛不住；解决：过期时间加随机值、集群部署、限流降级。

  6. Redis 主从复制原理？
    ① 从库连接主库，发送 SYNC 命令；
    ② 主库执行 bgsave 生成 RDB 文件，同时记录新的写命令；
    ③ 主库把 RDB 文件和新命令发给从库；
    ④ 从库加载 RDB，执行新命令，和主库数据同步；
    ⑤ 后续主库有写操作，实时同步给从库（增量复制）。

  7. Redis 哨兵（Sentinel）的作用？核心流程？
    哨兵是监控 Redis 集群的工具，核心作用：① 监控主从节点是否存活；② 主库故障时自动切换（选新主库）；③ 通知客户端主库地址变更。
    核心流程：主库宕机→哨兵集群投票→选一个从库升主→其他从库同步新主→通知客户端。

  8. Redis 集群（Cluster）原理？如何分片？
    Redis 集群是分布式方案，解决单节点容量和性能瓶颈：
    ① 采用哈希槽（16384 个）分片，槽位 = CRC16(key) % 16384；
    ② 每个节点负责一部分槽位，数据按槽位分布；
    ③ 主从复制：每个主节点有从节点，故障时从节点升主；
    ④ 客户端请求时，先定位槽位对应的节点，再发请求。

  9. Redis 分布式锁的实现方式？注意点？
    核心实现（SETNX）：SET key value NX EX 30（NX：不存在才设置，EX：自动过期）。
    注意点：① 设置过期时间，避免死锁；② 用 Lua 脚本保证解锁原子性（先判断 value 是自己的，再删除）；③ 过期时间要大于业务执行时间，或加续期（Redisson）。
    三、数据结构类（高频加分项）

  10. String 底层实现？
    底层是简单动态字符串（SDS），和 Java String 区别：① 可修改；② 预分配空间，减少扩容开销；③ 记录长度，获取长度 O (1)。
    小字符串用 embstr 编码，大字符串用 raw 编码。

  11. Hash 底层实现？
    小哈希：压缩列表（ziplist），节省内存；
    大哈希：哈希表（hashtable），查询更快；
    触发切换的条件：哈希元素数超过阈值，或单个元素值过大。

  12. ZSet 底层实现？
    小 ZSet：压缩列表；
    大 ZSet：跳表（skiplist）+ 哈希表；
    跳表优势：插入、删除、查询都是 O (logN)，比红黑树实现简单。

  13. Redis 过期键的删除策略？
    三种策略：
    ① 惰性删除：访问时才检查是否过期，过期则删除（节省 CPU，可能内存泄漏）；
    ② 定期删除：每隔一段时间，随机抽查部分过期键删除（平衡 CPU 和内存）；
    ③ Redis 用 “惰性删除 + 定期删除” 结合，配合内存淘汰策略兜底。

四、实战应用类（场景考察）

  1. 如何保证缓存和数据库的数据一致性？
    核心原则：最终一致性，常用方案：
    ① 先更数据库，再删缓存（避免并发问题）；
    ② 缓存删除失败则重试（比如用 MQ）；
    ③ 读多写少场景：加延迟双删（删缓存→更数据库→延迟 1s 再删缓存）。

  2. Redis 集群扩容怎么做？
    ① 新增节点，加入集群；
    ② 迁移哈希槽（把旧节点的槽位迁移到新节点）；
    ③ 迁移过程中，Redis 会自动处理请求，不影响业务（无缝扩容）。

  3. Redis 出现内存泄漏怎么排查？
    ① 用info memory查看内存使用情况；
    ② 用redis-cli –bigkeys找出大 key；
    ③ 检查过期键策略，是否有大量过期键没删除；
    ④ 检查业务代码，是否有大量无用 key 没清理。
    五、性能优化类（进阶考察）

  4. 如何优化 Redis 性能？
    ① 用批量操作（pipeline）减少网络请求；
    ② 避免大 key（拆分大 key，比如大 Hash 拆成多个小 Hash）；
    ③ 合理设置过期时间，避免内存浪费；
    ④ 开启持久化优化（比如 AOF 重写、RDB 定时调整）；
    ⑤ 集群部署，分摊压力。

  5. Redis 为什么要避免大 key？
    ① 删除大 key 会阻塞单线程，导致请求卡顿；
    ② 大 key 同步到从库耗时久，主从延迟大；
    ③ 占用内存多，内存淘汰时开销大。

  6. Redis 管道（pipeline）的作用？原理？
    作用：批量发送命令，减少网络往返次数，提升并发；
    原理：客户端把多个命令打包发送，Redis 一次性执行，批量返回结果（注意：pipeline 不是原子操作）

  • Redisson 分布式锁
    Redis 官方推荐，Hash+Lua 脚本保原子性，看门狗每 10 秒续期 30 秒；
    支持可重入 / 防误删 / 集群，项目按 SKU 加锁，lock 加锁、finally 解锁，避库存超卖。

Redis 常用数据类型 + 项目落地？
答：Hash 做航天云膜分仓库库存统计；String 存简单配置；ZSet 做 ES 搜索排序；List 存临时消息数据。

Redis 缓存穿透 / 击穿 / 雪崩怎么解？
答：穿透：布隆过滤器 / 空值缓存；击穿：热点 key 永不过期 / 互斥锁；雪崩：过期时间加随机值 + Redis+Caffeine 二级缓存。

Redisson 分布式锁比 Redis 原生 SETNX 好在哪？
答：SETNX 易造成死锁、需手动设置过期时间，还可能释放他人锁；Redisson 封装重入锁、自动续期、公平锁，解决网络延迟问题，项目高并发场景均使用

Redis

redis是一个非关系型数据库,项目中主要是用来存储热点数据,减轻数据库压力

持久化方式

它的持久化方式有两种,一种是RDB,另一种是AOF
RDB是以快照的方式来存储的,也是redis默认的持久化方式,每隔一段时间进行存储
AOF是在配置文件配置,每秒持久化一次或每次操作持久化一次。

Redis 支持哪些数据类型

我记得有5种数据类型,分别是
字符串
​列表（List）​：双端链表，支持 push/pop 操作。
​哈希（Hash）​：键值对的集合，适合存储对象。
​集合（Set）​：无序不重复元素集合，支持交集、并集等操作。
​有序集合（Sorted Set）​：元素按分数排序，适合排行榜。

Redis集群如何搭建

在项目中，我们是用 ​Redis Cluster 搭建集群，核心步骤如下：

​环境：6 节点（3 主 3 从），独立端口部署，关闭保护模式。
​配置：统一配置 cluster-enabled yes、cluster-replicas 1，指定唯一 cluster-config-file。
​创建：用 redis-cli –cluster create 命令一键生成集群，自动分配主从和槽位。
​验证：通过 CLUSTER INFO 和 CLUSTER NODES 检查状态，确保 cluster_state:ok。
​容灾：测试主节点宕机后从节点自动提升，保障业务连续性。
一句话总结：基于官方工具自动化部署，3 主 3 从，无中心架构，兼顾性能和高可用
