Docker

docker 容器
容器
发布日期:   2026-03-03

概述

Docker 是容器化技术，核心是将应用及依赖打包成镜像，运行镜像生成容器，实现「一次打包，到处运行」，解决 Java 开发中环境不一致、部署繁琐的问题（比如你项目中 Linux 服务器部署时的 JDK、中间件版本兼容问题）。

核心概念

镜像（Image）：只读的模板，包含运行应用的所有依赖（JDK、Redis、项目 jar 包等），镜像不能直接运行，是创建容器的基础。
容器（Container）：镜像的运行实例，可启动、停止、删除，每个容器是独立的隔离环境（类似轻量级虚拟机，但比虚拟机更高效，无内核级虚拟化）；比如运行 Java 项目镜像，生成的就是一个独立的项目容器。
仓库（Repository）：存储镜像的地方，分公有仓库和私有仓库;
公有：Docker Hub（官方）、阿里云镜像仓库、华为云镜像仓库（国内推荐，速度快）；
私有：公司内部搭建的镜像仓库（比如你项目中团队内部的镜像私服），用于存储公司自研项目镜像。
Dockerfile：构建自定义镜像的配置文件，通过编写指令（指定基础镜像、复制文件、执行命令等），让 Docker 自动构建符合需求的镜像（Java 开发最核心的实战技能，重点掌握）

Docker 与虚拟机的区别

我们项目中用 Docker 部署微服务和中间件，相比虚拟机，Docker 启动快、资源占用低，能快速搭建 Spring Cloud Alibaba 微服务集群，而且镜像统一管理，解决了开发、测试、生产环境不一致的问题，提升了部署效率。

Docker 操作模块划分

镜像操作→容器操作→网络操作→数据卷操作

镜像操作命令（核心：拉、查、建、删、推）

命令 功能说明 实战示例
docker pull 镜像名:版本 拉取镜像（版本不写默认 latest 最新版） docker pull openjdk:8-jdk-alpine（拉 Java8 镜像）、docker pull redis:6.2
docker images 查看本地所有镜像（含镜像名、版本、ID、大小） 直接执行，查看已拉取的镜像
docker rmi 镜像ID/镜像名:版本 删除本地镜像（-f 强制删除，镜像被容器使用时需先删容器） docker rmi openjdk:8-jdk-alpine、docker rmi -f 镜像ID
docker build -t 镜像名:版本 . 基于当前目录的 Dockerfile 构建自定义镜像（-t 指定镜像名和版本，.是 Dockerfile 所在目录） docker build -t stock-system:1.0 .（构建航天云膜库存系统镜像）
docker tag 原镜像名:版本 新镜像名:版本 给镜像打标签（用于推送到仓库） docker tag stock-system:1.0 registry.xxx.com/stock-system:1.0
docker push 镜像名:版本 推送镜像到仓库（需先登录仓库） docker push registry.xxx.com/stock-system:1.0
docker search 镜像名 搜索仓库中的镜像（仅查信息，不推荐用，直接去 Docker Hub 搜更全） docker search mysql
高频技巧：docker images -q 只显示镜像 ID，配合删除命令批量删镜像：docker rmi -f $(docker images -q)（谨慎使用，删所有本地镜像）

容器操作命令（核心：创、启、查、停、删、进）

核心语法：docker run [参数] 镜像名:版本 → 创建并启动容器，参数是重点，熟记常用参数！
核心运行参数（Java 项目部署必用，标注含义）
参数 含义
-d 后台运行容器（守护进程模式，生产环境必用）
-p 端口映射：宿主机端口：容器内端口（解决外部访问容器问题，Java 项目必配）
-v 数据卷挂载：宿主机目录 / 数据卷名：容器内目录（持久化数据，比如 MySQL 数据、项目日志）
–name 给容器指定自定义名称（方便管理，避免随机名称）
–restart=always 容器开机自启（生产环境必配，服务器重启后容器自动启动）
-e 设置容器内环境变量（比如 MySQL 的 ROOT 密码、Java 的 JVM 参数）
-it 交互式运行容器（进入容器终端，测试用）

常用容器命令（实战高频）
命令 功能说明 实战示例（航天云膜库存系统）
docker run -d -p 8080:8080 –name stock-system –restart=always stock-system:1.0 创建并后台运行 Java 项目容器，映射 8080 端口，指定名称，开机自启 核心命令，部署 Spring Boot 项目用
docker ps 查看运行中的容器（含容器 ID、名称、端口映射、镜像名） 直接执行，查看正在运行的服务
docker ps -a 查看所有容器（含运行中、已停止的） 查看容器启动记录，排查启动失败问题
docker start/stop 容器ID/容器名 启动 / 停止容器 docker start stock-system、docker stop stock-system
docker restart 容器ID/容器名 重启容器（项目更新配置、重启服务用） docker restart stock-system
docker rm 容器ID/容器名 删除容器（-f 强制删除运行中的容器） docker rm -f stock-system
docker exec -it 容器ID/容器名 /bin/bash 进入容器内部终端（排查容器内问题，比如查看日志、验证文件） docker exec -it stock-system /bin/bash
docker logs 容器ID/容器名 查看容器日志（-f 实时查看日志，Java 项目排错核心命令） docker logs -f stock-system（实时看项目运行日志）
docker inspect 容器ID/容器名 查看容器详细信息（比如容器内 IP、挂载目录、环境变量） 排查网络、挂载问题时用

高频技巧：docker ps -q 只显示运行中容器 ID，批量停止：docker stop $(docker ps -q)；批量删除已停止容器：docker rm $(docker ps -a -q)。

数据卷操作命令（持久化数据，必用）

数据卷操作命令（持久化数据，必用）
容器内的数据默认是临时的，容器删除后数据丢失，数据卷（Volume） 是 Docker 的持久化方案，将容器内的目录挂载到宿主机 / Docker 数据卷，实现数据持久化（比如 MySQL 的 /data 目录、Java 项目的 /logs 目录）。
命令 功能说明 实战示例
docker volume create 数据卷名 创建自定义数据卷 docker volume create mysql-data（MySQL 数据卷）
docker volume ls 查看所有数据卷 直接执行
docker volume inspect 数据卷名 查看数据卷详细信息（含宿主机实际挂载路径） docker volume inspect mysql-data
docker volume rm 数据卷名 删除数据卷（未被容器使用时才能删） docker volume rm mysql-data
docker volume prune 清理未被使用的所有数据卷（释放磁盘空间） 谨慎使用
实战用法：部署 MySQL 时挂载数据卷，保证数据不丢失
bash
运行
docker run -d -p 3306:3306 –name mysql57
–restart=always
-v mysql-data:/var/lib/mysql
-e MYSQL_ROOT_PASSWORD=123456
mysql:5.7

网络操作命令（微服务部署必用）

Docker 默认有 3 种网络：bridge（桥接，默认）、host（主机网络）、none（无网络），微服务集群中（比如你的 Spring Cloud Alibaba 项目），容器之间需要相互通信，常用自定义桥接网络（容器间可通过容器名互相访问，无需记 IP）。
命令 功能说明 实战示例（微服务集群）
docker network ls 查看所有 Docker 网络 直接执行
docker network create 网络名 创建自定义桥接网络 docker network create ms-network（微服务网络）
docker network connect 网络名 容器名 将容器加入自定义网络 docker network connect ms-network stock-system
docker network disconnect 网络名 容器名 将容器移出自定义网络 docker network disconnect ms-network stock-system
docker network rm 网络名 删除自定义网络 docker network rm ms-network
实战用法：创建微服务网络，所有微服务容器加入该网络，容器间可通过容器名:端口互相访问（比如 Nacos 容器名 nacos，其他微服务可通过nacos:8848访问）。
